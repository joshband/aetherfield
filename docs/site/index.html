Project · Status

An ambient reverb, built one proof at a time.

Aetherfield is a greenfield AUv3 reverb for iOS/iPadOS. Nothing ships until it's decided in writing, translated into an exact interface, implemented, and independently re-verified from disk — by a different pass than the one that wrote it.

Read the current-state guide or decision index before starting work. ADR-006's fixed diffusion/stereo evaluation baseline is implemented: DS-B Tasks 1–4, DS-1…DS-13, control forwarding, and the offline render tools are recorded in testing.md. Three owner listening rounds and Sol review close the DS-B Sonic acceptance component; no architectural revision is warranted. Product, host, UI, and modulation work remain owner-gated. This site summarizes the local records; published copies may lag.

How to read this project

Nothing is implied.

Every ADR states exactly what it does not decide. A topology choice never quietly becomes a stability claim.

Plans before code.

Every implementation increment gets a written interface plan first, independently verified, before a line of C++ is authorized.

Verified, not vouched for.

A second pass re-derives evidence from disk — rebuilding, recomputing arithmetic by hand — rather than trusting a summary.

What's deliberately absent

Modulation of any kind, the AUv3 wrapper, presets, external DSP dependencies, and a product signal path. The fixed diffusion/stereo route is an implemented evaluation baseline, not authorization to ship host or product behavior.

Architecture · Decision Records

Six decisions, with implementation tracked separately.

Durable architectural memory. Each ADR states its alternatives, what it decided and why, and — just as deliberately — what it refuses to decide yet.

ADR-001

Portable C++ host loop; AUv3 framework deferred

Accepted
Use C++20 + CMake for a portable static DSP library, CTest, and an offline WAV renderer — no third-party DSP dependency. The eventual AUv3 wrapper framework (native Apple APIs vs. JUCE) stays open.
Rejected: Xcode-only, SPM, JUCE-nowWhy: prove the engineering loop before committing to a deployment framework
ADR-002

Late reverb network: FDN, orthogonal matrix, per-line damping

Accepted
A Feedback Delay Network with a normalized Hadamard matrix beats Schroeder/Moorer comb+allpass, an allpass diffusion tank, and a general waveguide network — on echo-density growth, provable stability, and per-line frequency-dependent decay.
Rejected: comb+allpass, diffusion tank, general waveguideProves: ‖ΓA‖₂ ≤ max(gᵢ) < 1, for any delay lengthsExplicitly not proven: that it sounds good, or that N=8 is final
ADR-003

Damping filter, denormal handling, full-network lifecycle

Accepted
A unity-DC-gain one-pole damping filter, bounded-real by construction. Denormals handled by a deterministic ε = 1e-20 cutoff, not by relying on ARM's per-thread FPCR.FZ (which a host-created render thread doesn't inherit).
Rejected: first-order shelf, additive dither noiseGuarantees: exact silence in bounded timeNames: NS-1…NS-11, the fixed-network test gate
ADR-004

Initial parameters: Mix, Decay, Damp — and the automation/modulation line

Accepted
Three controls only. Decay is exponential (constant-JND), Damp is linear-dB, Mix is equal-power. A single-writer/single-reader atomic transport with a 20ms linear ramp — automation is proven safe; modulation remains prohibited, because no accepted control can reach the delay lengths or the matrix.
Deferred: Size, pre-delay, Mod Depth/Rate — 10 candidates in totalNames: PT-1…PT-9, the parameter-transition test gate
ADR-005

S2 fixture: line count and the concrete delay-length set

Accepted
Broke ADR-002's own deadlock — "defer N to measured evidence" needs the network built to measure it. Splits N_fixture = 8 (decided, for testing) from N_product (still deferred). Delay lengths: 8 primes, geometrically spaced 27–81ms, nearest-prime snapped, co-primality checked by direct gcd.
Fixture (48kHz): 1297, 1511, 1777, 2069, 2423, 2843, 3323, 3889 samplesHonest finding: Schroeder-Logan density criterion holds only to T60≈2.66s, not indefinitely
ADR-006

Input diffusion and stereo extraction

Implemented evaluation baseline
The fixed allpass, normalized-injection and interleaved-tap route is implemented as an evaluation baseline. What this deliberately does not claim

"Sonic quality is explicitly not claimed at S2 — any listening note taken at S2 is an observation, not an acceptance." — ADR-002
The S2 fixture's onset is structurally certain to sound like sparse, discrete echoes — no pre-delay, no diffusion exists yet. This is exactly what round 1's listening found; it is a property of the fixture, not evidence against the topology.

Implementation-time corrections are documented rather than hidden throughout: S2's delay-line capacity design and missing coefficient accessors (fixed), and PT's endpoint bit-exactness requirement and two vacuous-comparison test bugs (also fixed, caught by noticing an implausible exact-zero result rather than trusting a green checkmark). All recorded in their respective plan documents in docs/phases/, not silently patched.
